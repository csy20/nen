# Play Store screenshot plan

Capture these on a physical Android phone (or emulator) in **portrait**.
Use a recent device frame if you add one later. Keep overlays short and
benefit-focused. Recommended size: Play Console phone screenshots
(e.g. 1080×1920 or the current listing requirement).

Do **not** generate these in code — Csy will capture them on-device.

## Capture notes

- Use **dark theme** (Nen's default) so screenshots match the brand.
- Load a real library with **at least 10 songs**, album art where possible.
- Start a track before now-playing / visualizer shots so controls look live.
- Hide debug banners. Store listing screenshots should not show "DEBUG".
- If a screen is sparse, scroll so the interesting content fills the frame.

## Recommended set (6)

### 1. Library — songs list

- **Screen/state:** Home library tab with 10+ songs visible, now-playing card at the top showing a current track, floating bottom nav visible.
- **Why:** This is the core browse surface. A full list reads as "this is a real music player."
- **Overlay:** `Your local music. Ready to play.`

### 2. Now playing — controls

- **Screen/state:** Full-screen now playing with album art, title/artist, progress bar, shuffle / previous / play-pause / next / repeat. A track should be playing (pause icon).
- **Why:** Shoppers look for clear, large playback controls.
- **Overlay:** `Fast playback. Simple controls.`

### 3. Now playing — visualizer

- **Screen/state:** Same now-playing screen (or a tight crop) with the audio-reactive visualizer bars active. Equalizer entry visible if it fits without clutter.
- **Why:** The visualizer is a differentiator vs. generic file players.
- **Overlay:** `A visualizer that follows the music.`

### 4. Browse — albums

- **Screen/state:** Albums tab with a grid/list of several albums and artwork.
- **Why:** Shows local library organization, not a streaming catalog.
- **Overlay:** `Browse albums, artists, and folders.`

### 5. Playlists / favorites

- **Screen/state:** Playlists tab with at least one named playlist, **or** Favorites tab with several liked songs. If both are thin, prefer playlists with 2–3 items.
- **Why:** Signals you can organize a local library, not only play files.
- **Overlay:** `Playlists and favorites, kept on device.`

### 6. Settings — lightweight & local

- **Screen/state:** Settings with Audio & Playback and Appearance visible. Optional: scroll so "Rate this app" is *not* the hero — keep the shot about the product. Theme control should be readable.
- **Why:** Supports the "lightweight, no clutter" promise. Avoid a screenshot that only asks for a rating.
- **Overlay:** `Lightweight. No ads. Distraction-free.`

## Optional extras (if you have room)

- **Search:** Library search with a query and matching results. Overlay: `Find a track in your library.`
- **Equalizer:** 8-band EQ with a few bands adjusted. Overlay: `Shape the sound.`
- **Onboarding:** First welcome page only, if you want a "new app" story. Overlay: `A lightweight offline music player.` Skip this if the listing already has 6 strong product shots.

## Overlay style

- 4–8 words, sentence case, no exclamation spam.
- High-contrast text on a dim gradient at the top or bottom — never covering album art faces or the play button.
- Same font weight and placement on every shot so the set looks like one listing.
